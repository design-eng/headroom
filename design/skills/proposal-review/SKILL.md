# 제안서 PPT 규격 검토

제안서는 납품물이다. 색 하나, 폰트 하나가 어긋나면 "대충 만들었다"는 인상이 남는다.
사람 눈으로 70장을 훑으면 반드시 놓친다. 기계가 잡을 수 있는 건 기계에 맡기고,
사람은 판단이 필요한 곳에 집중한다 — 이 스킬은 그 분담을 위해 있다.

**읽기 전용이다.** 파일을 수정하지 않는다. 수정은 사용자가 결과를 보고 결정한 뒤
`ppt-margin-fit` · `ppt-design-cleanup` · `ppt-round-4pt` 같은 수정 스킬로 한다.

## 실행

```bash
python3 scripts/check_ppt.py <파일.pptx>
python3 scripts/check_ppt.py <파일.pptx> --slides 29,36,59   # 특정 장만
python3 scripts/check_ppt.py <파일.pptx> --json              # 기계 판독용
```

`python-pptx`가 없으면 `pip install python-pptx`. 종료코드는 위반이 있으면 1, 없으면 0이다.

스크립트를 직접 수정하지 말고 그대로 돌린다. 규격값은 `ppt-design-system-v2`에서 왔고,
스크립트를 손대면 두 문서가 어긋나 나중에 어느 쪽이 맞는지 알 수 없게 된다.

## 검사하는 6가지

| 항목 | 기준 | 근거 |
|---|---|---|
| **색상** | `#1B2B41` `#3A88B4` `#66B2E0` `#D5D2CA` `#333333` + 흑백 | 구버전 색은 치환 대상까지 함께 알려준다 |
| **폰트** | Pretendard 계열, `latin`·`ea`·`cs` 세 개 모두 지정 | `ea` 누락 시 한글이 맑은 고딕으로 렌더된다 |
| **크기** | 하한 11pt (표 셀만 예외) | 그 아래는 인쇄·빔 프로젝터에서 안 읽힌다 |
| **마진** | 좌우 46~914, 상하 99~464 | 전폭 스트립(0~960)은 예외 처리됨 |
| **라운드** | `adj = round(50800 / min(cx,cy) × 100000)`, 상한 50000 | 실치수 4pt. adj가 도형마다 다른 게 정상이다 |
| **감산** | 면+테두리 동시 금지, 그림자 금지, 테마 `lnRef` 누수 | 제거 1순위는 외곽 컨테이너다 |

좌표는 정수로 비교하지 않는다(`99.0812…` 같은 값이 흔하다). 허용오차 1pt를 둔다.

## 보고 형식

스크립트 출력을 그대로 붙여넣지 말고, 아래 틀로 정리해서 전한다.
사용자가 알고 싶은 건 "몇 건이냐"가 아니라 "무엇부터 손대야 하냐"다.

```
## 검토 결과 — <파일명> (<n>장)

**합계 <n>건** · 색상 n · 폰트 n · 크기 n · 마진 n · 라운드 n · 감산 n

### 먼저 손댈 것
<가장 많이 반복되는 위반 2~3개. 한 번 고치면 여러 장이 동시에 해결되는 것 우선>

### 페이지별
<페이지당 3건까지만. 그 이상이면 "외 n건"으로 접는다>

### 사람이 봐야 하는 것
<아래 목록 중 해당되는 것>
```

### 수정 순서는 고정이다

**마진 → 감산 → 색·폰트 → 라운드.**

배치가 바뀌면 나머지가 다시 틀어지기 때문이다. 색부터 만지면 두 번 일한다.
보고할 때도 이 순서로 나열한다 — 스크립트가 이미 그 순서로 정렬해서 출력한다.

### 반복 위반을 먼저 짚는다

같은 색, 같은 폰트가 30장에서 나오면 30건이 아니라 **한 건의 일괄 치환**이다.
페이지별 나열보다 이걸 먼저 말한다. 사용자의 시간을 가장 크게 아끼는 지점이다.

## 이 스크립트가 못 잡는 것

정직하게 함께 전한다. "위반 없음"이 "완벽하다"는 뜻이 아니기 때문이다.

- **컴포넌트 규격** — 카드 높이 76, 행 간격 14, 태그 폭 150 같은 값은 문맥이 있어야 판단된다
- **강조 1개 원칙** — 한 페이지에 활성(네이비 면) 카드는 한 장만. 병렬 항목은 활성이 없어야 한다
- **밴드 간격 24pt 균등** — 밴드의 경계를 사람이 정해야 측정할 수 있다
- **페이지 유형 적합성** — 이 내용이 카드형 2단인지 선 기반 표인지
- **시각적 겹침·명암비** — `verify_slide_visual`로 렌더해서 봐야 한다
- **문구** — 요청이 없으면 손대지 않는다

검사가 0건으로 끝나면 이 목록을 근거로 "기계 검사는 통과했고, 남은 건 눈으로 볼 영역"이라고 말한다.

## 스코프 규칙

`ppt-design-system-v2`의 0절을 따른다.

- 사용자가 페이지를 지정하면 `--slides`로 **그 페이지만** 검사한다.
  다른 페이지가 어긋나 보여도 보고서 말미에 한 줄로만 언급하고 고치지 않는다.
- 슬라이드 마스터·레이아웃은 검사 대상이 아니다.
- 슬라이드 밖 상태 태그(녹색·빨강 세로 블록)는 디자인 요소가 아니므로 무시한다.

## 예시

**입력:** "코오롱 제안서 29, 36페이지 규격 맞는지 봐줘"

**실행:** `python3 scripts/check_ppt.py 코오롱_제안서.pptx --slides 29,36`

**출력:**

```
## 검토 결과 — 코오롱_제안서.pptx (29·36페이지)

**합계 7건** · 색상 3 · 폰트 2 · 마진 1 · 라운드 1

### 먼저 손댈 것
- `#00629F`가 두 장에서 3번 — 전부 `#3A88B4`(브랜드 블루)로 일괄 치환하면 색상 3건이 한 번에 끝난다
- 36페이지 Phase 바 3개의 `ea` 누락 — 한글이 맑은 고딕으로 렌더되고 있다

### 페이지별
**29페이지**
- [마진] 카드_04 — 우측 끝 928pt > 914. 폭을 14 줄인다
- [색상] 헤더바 — #00629F → #3A88B4

**36페이지**
- [폰트] Phase바_1~3 — latin만 있고 ea·cs 누락
- [라운드] 결론스트립 — adj=16667, 높이 32pt 기준 정답은 12500

### 사람이 봐야 하는 것
- 36페이지에 네이비 활성 카드가 2장으로 보인다. 병렬 항목이면 활성은 없어야 한다
- 두 장 모두 밴드 간격은 렌더해서 확인이 필요하다
```

숫자만 나열하지 말고 **한 번에 끝나는 것**을 먼저 짚는 것이 이 보고의 핵심이다.
